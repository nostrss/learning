Reference · WebSocket 프로토콜 열림 핸드셰이크 치트시트

클라이언트 요청 (RFC 6455 §4.1)

GET /path HTTP/1.1          ← 반드시 GET, HTTP/1.1 이상
Host: server.example.com     ← 필수
Upgrade: websocket           ← 필수, 값 대소문자 무관
Connection: Upgrade          ← 필수
Sec-WebSocket-Key: [base64]  ← 필수, 무작위 16바이트, 연결마다 새로
Sec-WebSocket-Version: 13    ← 필수, 항상 13
Origin: https://...          ← 브라우저 클라이언트는 필수
Sec-WebSocket-Protocol: ...  ← 선택, 서브프로토콜 협상
Sec-WebSocket-Extensions: ...← 선택, 예: permessage-deflate

서버 응답 (§4.2)

HTTP/1.1 101 Switching Protocols
Upgrade: websocket
Connection: Upgrade
Sec-WebSocket-Accept: [계산값]  ← 아래 공식, 틀리면 클라이언트가 연결 실패 처리

Accept 계산 공식 (§1.3)

Accept = base64( SHA1( Sec-WebSocket-Key + "258EAFA5-E914-47DA-95CA-C5AB0DC85B11" ) )

예시 (RFC 원문):
Key:    "dGhlIHNhbXBsZSBub25jZQ=="
Accept: "s3pPLMBiTxaQ9kYGzzhZRbK+xOo="

빠른 사실

URI 스킴ws:// (기본 포트 80) · wss:// (기본 포트 443, TLS)
101 이후해당 TCP 연결에는 HTTP가 아닌 WebSocket 프레임만 흐름
101 외 응답클라이언트는 핸드셰이크 실패로 처리 (426 = 버전 불일치 안내)
표준화프로토콜: IETF RFC 6455 · 브라우저 API: WHATWG
HTTP/2·3 위에서Upgrade 없음 → Extended CONNECT (RFC 8441 / RFC 9220)
