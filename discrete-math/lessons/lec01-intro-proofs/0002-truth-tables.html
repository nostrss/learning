6.042J · Lesson 0002 · Lecture 1 · 교재 §1.1논리 연산자와 진리표

일상 언어는 애매하다. 수학은 명제를 조합하는 단어들 — NOT, AND, OR, IMPLIES — 에 진리표(truth table)로 정확한 정의를 박아 넣는다. 오늘은 그 정의들을 하나씩 확인한다.

미션 연결. 이 진리표들은 이미 매일 쓰고 있다: !, &&, ||가 정확히 NOT, AND, OR다. 새로 배우는 건 하나 — IMPLIES. 코드에는 연산자가 없지만, "입력이 유효하면 출력은 정렬되어 있다" 같은 스펙 문장이 전부 IMPLIES이고, 이 연산자의 정의가 직관과 어긋나는 지점이 수학 문장을 오독하는 첫 번째 함정이다.

1. Boolean 변수

이제 명제의 내용("모든 인간은 죽는다")은 잠시 잊고, 명제들이 어떻게 조합되는지만 본다. 그래서 명제를 변수 P, Q로 대신 쓴다. 이 변수들은 T(참) 또는 F(거짓)만 가질 수 있다 — 발명자 George Boole의 이름을 따 Boolean variable이라 부른다. (boolean 타입의 그 Boole이다.)

2. NOT, AND, OR — 아는 것들

진리표는 변수의 모든 조합에 대해 명제의 진위를 나열한 표다. 예상대로다:

PQP AND QP OR QP XOR Q
TTTTF
TFFTT
FTFTT
FFFFF

한 가지 주의: 수학의 OR는 둘 다 참이어도 참이다(첫 행). "케이크를 먹어도 되고, 아이스크림을 먹어도 된다"라고 수학자가 말하면 둘 다 먹어도 된다는 뜻. 코드의 ||도 수학 OR와 같은 포함적(inclusive) 정의다.

XOR(exclusive-or)는 "둘 다"를 배제하고 싶을 때 쓰는 별도 연산자다. 위 표에서 OR와 비교하면 첫 행(둘 다 참)만 다르다: P와 Q의 진위가 서로 다를 때, 정확히 그때만 참이다. "케이크 아니면 아이스크림, 하나만 골라" — 디저트를 둘 다 집으면 거짓. JavaScript에는 논리 XOR 연산자가 따로 없는데, boolean끼리라면 이걸로 충분하다:

const xor = (p, q) => p !== q;   // 진위가 다르면 true — XOR 진리표 그대로

"다르면 참"이라는 성질 때문에 XOR는 토글(같은 값을 두 번 적용하면 원상복구)이나 두 상태가 어긋났는지 검사하는 데 쓰인다. 지금은 진리표만 정확히 기억하면 충분하다.

JS 번역 — 진리표는 "모든 조합의 완전 열거"다. 변수 n개면 2ⁿ행. 코드로 쓰면 중첩 루프 그 자체다: 
for (const p of [true, false])
  for (const q of [true, false])
    console.log(p, q, '→', p && q, p || q, p !== q);  // AND, OR, XOR 열이 그대로 출력된다
위 표는 이 루프의 출력을 옮겨 적은 것뿐이다. 변수가 유한하고 값이 T/F뿐이라서 전수 검사가 가능하다는 것 — 이게 진리표가 예시 확인(레슨 1)과 달리 증명으로 인정되는 이유다. 모든 경우를 빠짐없이 확인했으니까.

3. IMPLIES — 가장 직관에 어긋나는 연산자

교재의 정의:

PQP IMPLIES Q
TTT(tt)
TFF(tf)
FTT(ft)
FFT(ff)

거짓인 행이 단 하나 — P가 참인데 Q가 거짓일 때뿐이다. 교재가 외우라고 강조하는 한 문장:

An implication is true exactly when the if-part is false or the then-part is true. — Mathematics for Computer Science, §1.1.2 · 번역: implication은 if-부분이 거짓이거나 then-부분이 참일 때, 정확히 그때 참이다.

이상하게 느껴지는 건 (ft)와 (ff) 행이다. 교재의 예:

"If pigs can fly, then you can understand the Chebyshev bound." — 돼지는 날 수 없으므로 P는 거짓. 그럼 당신이 Chebyshev bound를 이해하든 못 하든 이 명제는 참이다(ft 또는 ff 행). 전제가 거짓이면 전체는 자동으로 참 — 이걸 공허하게 참(vacuously true)이라 한다.

개발자 번역. 스펙 "입력이 유효하면(P) 출력은 정렬되어 있다(Q)"를 생각하자. 유효하지 않은 입력을 넣었더니 이상한 출력이 나왔다 — 스펙 위반인가? 아니다. P가 거짓이므로 스펙은 여전히 지켜지고 있다(공허하게 참). implication이 깨지는 경우는 단 하나: 유효한 입력(P 참)에 정렬 안 된 출력(Q 거짓)이 나올 때. 테스트로 스펙 위반을 잡으려면 (tf) 행을 노려야 한다는 뜻이다.

반대로 거짓인 implication의 예: "If the moon shines white, then the moon is made of white cheddar." 달은 희게 빛나고(P 참) 달은 치즈가 아니므로(Q 거짓), (tf) 행 — 거짓.

흥미로운 활용: "If the Riemann Hypothesis is true, then x² ≥ 0 for every real number x." Riemann 가설의 진위는 아무도 모르지만, 결론 Q가 확실히 참이므로 (tt) 아니면 (ft) 행 — 어느 쪽이든 전체는 참이다. 전제를 몰라도 판정이 끝난다.

Q&A — "IMPLIES를 JavaScript로 설명해달라." 코드에 연산자가 없어 낯설지만, 함수로 쓰면 한 줄이다: 
const implies = (p, q) => !p || q;

implies(true,  true);   // true   (tt)
implies(true,  false);  // false  (tf) ← 유일한 거짓
implies(false, true);   // true   (ft)
implies(false, false);  // true   (ff)
왜 !p || q인가? IMPLIES는 조건부 약속이다: "비가 오면(P) 우산을 가져간다(Q)". 약속이 깨지는 경우는 비 왔는데 우산 안 가져간 것뿐 — 비가 안 왔으면 뭘 하든 약속 위반이 아니다(공허하게 참). 
const broken = (rain, umbrella) => rain && !umbrella;  // 깨지는 유일한 경우
// 약속이 지켜짐 = !(p && !q) = !p || q   ← 드모르간 법칙
실무에서는 이미 guard clause로 쓰고 있다: 
function process(user) {
  if (!user.isAdmin) return;   // P 거짓 → 공허하게 참, 위반 불가능
  doAdminThing(user);          // P 참일 때만 Q를 책임진다
}
그리고 레슨 3의 예고: implies(p, q)와 implies(q, p)(역)는 다른 명제지만, implies(!q, !p)(대우)는 같은 명제다. "비 오면 우산 챙긴다"가 참이어도 "우산 챙겼으면 비 온다"는 따라 나오지 않는다.

4. IFF — 논리적 동치

"P if and only if Q"(줄여서 iff)는 P와 Q의 진위가 같다는 주장이다: 둘 다 참이거나, 둘 다 거짓이거나.

PQP IFF Q
TTT
TFF
FTF
FFT

예: 모든 실수 x에 대해 "x² − 4 ≥ 0 iff |x| ≥ 2"는 참이다. 어떤 x에서는 양쪽 다 참이고, 다른 x에서는 양쪽 다 거짓이지만 — 항상 같이 움직이므로 iff 전체는 항상 참.

JS 번역. boolean끼리의 IFF는 정확히 ===다 (XOR가 !==였던 것의 반대): 
const p = x => x * x - 4 >= 0;
const q = x => Math.abs(x) >= 2;
// 위 iff의 주장: 모든 실수 x에서 p(x) === q(x)

[0, 1, 2, 3, -5].every(x => p(x) === q(x));  // true — 하지만 이건 예시 5개 확인일 뿐
마지막 줄이 중요하다: x가 T/F가 아니라 실수라서 전수 검사가 불가능하다 — 진리표(2ⁿ행 완전 열거)가 통하는 세계 밖이다. "모든 실수에서"를 확정하려면 레슨 5부터 배울 증명이 필요하다. 진리표로 끝나는 명제와 증명이 필요한 명제의 경계가 여기다.

5. 기호 표기

영어기호코드
NOT(P)¬P!p
P AND QP ∧ Qp && q
P OR QP ∨ Qp || q
P IMPLIES QP → Q!p || q
P IFF QP ↔ Qp === q

교재는 기호보다 단어(AND, IMPLIES)를 주로 쓴다 — 우리도 그렇게 한다. 표의 코드 열을 보면 IMPLIES가 !p || q와 같음을 진리표로 직접 확인할 수 있다. "if-부분이 거짓이거나 then-부분이 참"이라는 그 문장 그대로다.
