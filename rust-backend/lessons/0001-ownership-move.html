Ownership: 값의 주인은 한 명

목표: let b = a; 한 줄이 TypeScript와 Rust에서 왜 다른 뜻인지 설명하고, E0382 에러를 직접 만들고 직접 고친다.

1. 네가 이미 아는 것 (TypeScript)

TypeScript

const a = { name: "jintagi" };
const b = a;      // 같은 객체를 가리킴
b.name = "ferris";
console.log(a.name); // "ferris"

무슨 일이 일어나나

힙에 객체 하나, 그걸 가리키는 참조가 둘. 누가 "주인"인지 아무도 신경 안 쓴다. 참조가 다 사라지면 GC가 언젠가 치운다.

2. Rust의 규칙 세 줄

The Rust Book이 정의하는 ownership 규칙은 딱 세 개다 (ch04-01 · Ownership Rules):

  1. Rust의 모든 값에는 owner가 있다.
  2. owner는 한 번에 하나뿐이다.
  3. owner가 scope를 벗어나면 값은 drop(해제)된다.
GC가 없다는 뜻. 3번 규칙이 메모리 해제의 전부다. "힙 데이터를 누가 해제하는가"의 답이 컴파일 타임에 정해지므로, 주인이 둘이면 두 번 해제(double free)가 생긴다. 그래서 2번 규칙이 필요하다.

3. 그래서 let s2 = s1;은 "이동(move)"이다

fn main() {
    let s1 = String::from("hello");
    let s2 = s1;              // 소유권이 s1 → s2 로 이동
    println!("{s1}, world!"); // ❌ s1은 더 이상 주인이 아님
    println!("{s2}");
}

컴파일러 출력 (rustc 1.95.0에서 실제 실행):

error[E0382]: borrow of moved value: `s1`
 --> src/main.rs:4:16
  |
2 |     let s1 = String::from("hello");
  |         -- move occurs because `s1` has type `String`,
  |            which does not implement the `Copy` trait
3 |     let s2 = s1;
  |              -- value moved here
4 |     println!("{s1}, world!");
  |                ^^ value borrowed here after move
  |
help: consider cloning the value if the performance cost is acceptable
  |
3 |     let s2 = s1.clone();
  |                ++++++++

TS에서는 "참조 복사"였던 것이 Rust에서는 주인 교체다. 힙의 "hello"는 그대로 있고, 그걸 책임지는 변수가 s2로 바뀌었을 뿐이다. s1은 컴파일러가 "죽은 변수"로 취급한다 (ch04-01 · Move).

진짜로 두 개가 필요하면 명시적으로 s1.clone() — 힙 데이터를 통째로 복사한다. 컴파일러 힌트 그대로.

4. 예외: Copy 타입은 이동하지 않는다

let a: i32 = 5;
let b = a;          // 복사. a도 b도 살아 있음
println!("{a} {b}"); // 5 5

크기가 컴파일 타임에 정해져 스택에 통째로 올라가는 타입은 Copy trait을 구현하고 있어 대입 시 복사된다: 모든 정수, bool, 모든 부동소수점, char, 그리고 Copy 타입만으로 이루어진 튜플 (ch04-01 · Stack-Only Data: Copy).

경험칙. 힙을 쓰는 타입(String, Vec, 구조체 대부분)은 move. 숫자처럼 작은 것은 copy. 헷갈리면 컴파일러가 "does not implement the Copy trait"라고 말해준다.

5. 함수 호출도 move다

TS에서 함수에 객체를 넘기면 참조가 넘어간다. Rust에서 String을 넘기면 소유권이 함수 안으로 들어간다.

fn shout(name: String) -> String {
    name.to_uppercase()
}

fn main() {
    let name = String::from("jintagi");
    let loud = shout(name);   // name의 소유권이 shout으로 이동
    println!("{loud}");
    println!("{name}");       // ❌ E0382: borrow of moved value: `name`
}

이게 이번 레슨의 과제다. 아래에서 직접 고친다.

6. 퀴즈

Q1. let s2 = s1; (둘 다 String) 직후 상태는?

String은 Copy가 아니므로 move. 힙 데이터는 하나, 주인만 바뀐다. 복사하려면 명시적으로 .clone().

Q2. let b = a; 뒤에도 a를 계속 쓸 수 있는 타입은?

Copy 타입만으로 이루어진 튜플은 Copy. String과 Vec은 힙을 소유하므로 move.

Q3. fn f(s: String)을 f(name)으로 호출한 뒤 name은?

파라미터 타입이 String(소유 타입)이면 호출은 move. 돌려받으려면 함수가 반환해야 한다. 다음 레슨에서 더 좋은 방법(&)을 배운다.

7. 과제: E0382를 두 가지 방법으로 고치기 (10분)

  1. 터미널: cd ~/github/learning/rust-backend && mkdir -p exercises && cd exercises && cargo new rust-01-ownership && cd rust-01-ownership
  2. src/main.rs에 위 5번의 shout 코드를 복붙 말고 직접 타이핑한다.
  3. cargo run → E0382를 눈으로 확인한다. 에러 메시지의 value moved here 줄이 어디를 가리키는지 읽는다.
  4. 방법 A: shout의 시그니처를 바꾸지 않고 main만 고쳐서 통과시켜라.
  5. 방법 B: .clone()을 쓰지 않고, shout가 name의 소유권을 돌려주도록 시그니처와 본문을 바꿔라. 힌트: 반환 타입이 튜플이 된다.
  6. 두 방법 모두 출력이 JINTAGI 다음 줄 jintagi여야 한다.
힌트 (막혔을 때만)

방법 A: 컴파일러가 help:에 이미 답을 써 줬다.
방법 B: fn shout(name: String) -> (String, String). 본문에서 to_uppercase()는 새 String을 만들고 name은 건드리지 않으니, 둘 다 돌려줄 수 있다. main에서는 let (name, loud) = shout(name);로 받는다.

완성한 두 버전을 채널에 올리면 리뷰해 줄게. 방법 B가 "왜 불편한지" 한 줄로 같이 써 주면 더 좋다 — 그 불편함이 다음 레슨의 출발점이다.

이번 레슨의 승리: E0382를 보고 "아, 여기서 move됐구나"라고 읽을 수 있게 됐다. 이 에러는 앞으로 수백 번 만난다.
