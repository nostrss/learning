# 종료 핸드셰이크의 비동기성을 스스로 간파함 — 경쟁 상태를 질문으로 도출

레슨 3(종료 핸드셰이크)을 읽고 "CLOSING 도중 서버가 처리하던 작업이 뒤늦게 도착할 수 있나?"를 스스로 질문함. 가르치지 않은 경쟁 상태를 상태 기계 설명만으로 추론해낸 것 — CLOSING이 순간이 아니라 구간이라는 이해가 자리 잡았다는 증거. §5.5.1(지연된 Close 응답 허용)과 WHATWG의 OPEN 가드(클라이언트 발 close() 시 뒤늦은 메시지 조용히 유실)로 답함.

**Evidence** — 질문 자체가 비동기 구간의 존재를 전제로 함 (2026-07-26).

**Implications** — 상태 전이 다이어그램에서 스스로 경계 조건을 뽑아내는 수준. 레슨 4(ping/pong) 때 "pong이 CLOSING 중 도착하면?" 같은 경계 질문을 선제적으로 다루면 좋음. 실습(Node 최소 서버 구현) 투입 준비가 거의 됨.
