Reference · WebSocket 프로토콜 close code 치트시트

정의된 코드 (RFC 6455 §7.4.1)

코드의미와이어브라우저 close()
1000정상 종료가능가능
1001떠남 — 서버 셧다운, 페이지 이탈가능불가
1002프로토콜 오류가능불가
1003수용 불가한 데이터 타입 (텍스트만 받는데 바이너리 등)가능불가
1004예약 — 의미 미정의불가불가
1005합성: Close 프레임에 코드가 없었음금지불가
1006합성: Close 프레임 없이 비정상 끊김 (모든 연결 실패 포함)금지불가
1007페이로드가 메시지 타입과 불일치 (예: Text인데 깨진 UTF-8)가능불가
1008정책 위반 (범용 — 이유를 숨길 때도)가능불가
1009메시지가 너무 큼가능불가
1010확장 협상 실패 (클라이언트 전용 — 서버는 핸드셰이크를 거부하면 됨)가능불가
1011서버 내부 오류 (서버판 500)가능불가
1015합성: TLS 핸드셰이크 실패금지불가

범위 관할 (§7.4.2)

0–999사용하지 않음
1000–2999프로토콜·확장 스펙 전용
3000–3999라이브러리·프레임워크 (IANA 등록제)
4000–4999앱 자유 사용 — 자체 종료 사유는 여기 (예: 4001 세션 만료)

빠른 사실

Close 프레임 페이로드코드 2바이트(빅엔디안) + UTF-8 reason ≤123바이트 (컨트롤 프레임 한도 125 − 2)
브라우저 close(code) 허용값1000 또는 3000–4999만. 그 외 InvalidAccessError (WHATWG). 서버 측 라이브러리는 이 제약 없음 — 와이어 규칙만 지키면 프로토콜 코드(1011 등) 전송 가능
wasCleanClose 핸드셰이크 완료 후 TCP가 닫혔는가 (§7.1.4)
1006의 의미"서버가 보낸 코드"가 아니라 "아무 Close 프레임도 못 받았다"는 로컬 보고
재연결 권고랜덤 초기 지연(0~5초) + 지수 백오프 — 스펙 SHOULD (§7.2.3)
TCP 종료 순서서버가 먼저 닫는 것이 SHOULD (TIME_WAIT를 서버가 부담, §7.1.1)
