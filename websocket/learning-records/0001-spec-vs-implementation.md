# 핸드셰이크 구조를 소화하고, 스펙과 구현체의 관계를 구분하기 시작함

Lesson 0001 이후 사용자가 "Accept 계산은 백엔드 개발자가 직접 구현하나, 브라우저처럼 자동인가"를 질문함. 핸드셰이크 메커니즘 자체는 이해했고, 관심이 "스펙에 뭐라고 쓰여 있나"에서 "그걸 누가/어디서 구현하나"로 확장됨. 브라우저(플랫폼 내장) vs 서버(라이브러리가 RFC 6455 구현)의 비대칭을 설명받고 수긍함.

**Evidence** — 질문 자체가 핸드셰이크의 역할 분담을 전제로 함. 퀴즈 완료 여부는 미확인.

**Implications** — 향후 레슨에서 "이 스펙 조항을 누가 구현하는가(브라우저/라이브러리/앱 코드)" 축을 명시하면 잘 흡수할 것. 라이브러리 없이 Node http 모듈만으로 최소 WebSocket 서버를 만드는 실습을 프레임 레슨(0002) 이후 후보로 예약함.
