# readyState의 한계를 질문으로 도출 — 래퍼 상태 기계의 존재 이유를 이해함

레슨 4에서 "pong이 안 와서 재연결 중일 때 readyState는?"을 질문함. 답을 통해 (1) 죽음 판정 순간에도 readyState는 OPEN(판정 주체는 래퍼), (2) WebSocket 인스턴스는 일회용이고 재연결 = 새 객체, (3) "재연결 중" 상태는 스펙에 없으므로 래퍼가 자체 상태 기계를 갖는 것이 필연임을 확인함. 본인이 직접 구현한 상태관리 래퍼의 설계 근거가 스펙의 공백에서 나온다는 것을 이해한 것.

**Evidence** — 하트비트 죽음 판정과 상태 기계를 스스로 교차시킨 질문 (2026-07-26). [[0004-closing-race-insight]]와 같은 계열의 경계 질문.

**Implications** — 스펙 상태 기계 vs 앱 상태 기계의 구분이 잡힘. 실습(Node 최소 서버) 또는 래퍼 설계 리뷰 세션을 하면 배운 것이 실무 코드로 연결될 최적기.
